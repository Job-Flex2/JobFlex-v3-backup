# QA-харнес (Playwright-скрипты функциональных проверок)

Скрипты, которыми прогонялись все страницы (логин → клики по каждой кнопке →
проверки → уборка за собой в базе). Не тест-фреймворк — обычные node-скрипты.

## Установка (однократно, из этой папки)
```bash
cd scripts/qa
npm install            # ставит playwright из package.json
npx playwright install chromium
```

## Запуск (dev-сервер на localhost:$QA_PORT, по умолчанию 3000; или QA_BASE_URL целиком)
```bash
node fin-test.js       # Financials — 21 проверка
node sub-test.js       # Subscription
node roof-test.js      # Roof: node seed-roof.js up → сохранённый замер в QA Co, открывается из Recent без покупки
node fence-test.js     # Fence
node phone-test.js     # Phone (сначала node seed-phone.js up, после — down)
node messages-test.js  # Messages
node ann-test.js       # Announcements — /admin/announcements (cookie jf_admin); ничего не публикует
node reviews-test.js   # Reviews (+ reviews-chips.js)
node trade-test.js     # Trade (+ trade-tail.js)
node ref-test.js       # Referrals (сид конверсий — внутри инструкции сессии)
node reports-test.js   # Reports
node fixpass-smoke.js  # смоук фикс-пасса (hover/press/фокус/клавиатура)
node shot.js /dashboard /dashboard/leads   # логин + скриншоты любых роутов
```

Примечания:
- Git Bash: запускать с `MSYS_NO_PATHCONV=1`, иначе `/dashboard` превратится в путь Windows.
- seed-*.js `up|down` — сид/уборка тестовых данных (звонки, кэш крыши).
- Роут /dashboard/beige — A/B-копия Overview со старым бежевым видом (удалить папку
  src/app/dashboard/beige, когда сравнение больше не нужно).

## Весь набор одной командой
```bash
node scripts/qa/run-all.js            # из корня проекта; --checks или --pages — половина набора
```
Строка на скрипт: PASS / FAIL / STALE. STALE — скрипт написан под страницу, которую с тех пор
перестроили или перенесли; он говорит об этом и отходит в сторону (`--force` запускает всё равно).

## Организация и данные (2026-09-21)
- Все скрипты входят под `qa@acme.test` и работают ТОЛЬКО в организации **QA Co** (slug `qa-co`).
  Лимиты — на организацию; прогон внутри организации владельца тратил его лимиты.
- `_qa.js` — общий вход (одна сессия на весь набор: тормоз входа — 8 попыток за 15 минут),
  запуск браузера (свой Chromium или системный Chrome) и `withWorld()`.
- `_world.js up|down|status` — записи, которые нужны страницам (двое коллег, два диалога, клиент,
  три завершённые работы, реферальный код с тремя конверсиями; по запросу — отзыв, закрытый пост).
  Создаются в QA Co перед скриптом и удаляются после него, прошёл он или нет.
- `seed-phone.js`, `seed-roof.js` — тоже в QA Co (организация ищется по slug).
- Платного не делаем: чтение чека в `fin-test.js` обрывается на сети (это vision-вызов), адрес в
  `fence-test.js` — из кэша участков, `roof-test.js` работает с сохранённым замером; кнопки покупки
  (Measure this roof, Re-measure) — в `FORBIDDEN_CONTROLS`, нажатие гасится и роняет прогон.

## Страховка (2026-09-21)
Перед любым действием `_world.js`, `run-all.js` и общий вход `_qa.js` проверяют три вещи, и при
любом несовпадении скрипт завершается с ошибкой, не сделав ни клика, ни записи:
- **где** — `DATABASE_URL` (у процесса, в `.env` и в `.env.local`) указывает на локальную dev-базу:
  файл SQLite или сервер на этой машине. Значения не печатаются;
- **кто** — `qa@acme.test`, активная организация — QA Co, и ни одного места в организации, где
  работают люди (одноразовые организации самих проверок — можно). В браузере дополнительно
  сверяется, под кем открыта сессия;
- **что** — `FORBIDDEN_CONTROLS` в `_world.js`: удаление аккаунта/организации, отмена подписки,
  отправка писем наружу, платные поиски. Список ставится в каждую страницу до первой навигации:
  нажатие гасится в странице, скрипт падает с кодом 1.
`qa-guard.check.js` проверяет саму страховку. `settings-test.js` удалён: он нажимал Delete account.

## `server-only` вне Next (2026-09-23)
`src/lib/sdk/stripe.ts`, `lib/crypto/secretBox.ts`, `lib/oauthState.ts` импортируют маркер `server-only`.
Next подставляет свой встроенный (пустой на сервере); в обычном node его нет — пакет не в
зависимостях, а npm-версия тоже бросает исключение. Чек, который доходит до этих модулей через tsx,
падает на импорте. Общий стаб — `_server-only.ts`: подключать ПЕРВЫМ импортом чека,
`import "./_server-only";`, до всего, что тянет `src/lib`.

## Серверные действия от имени участника (2026-10-12)
`_actionHarness.ts` — общий вход для проверок доступа: подключать ПЕРВЫМ импортом. Он выключает сеть
(fetch бросает), обнуляет ключи внешних сервисов и подменяет `next/headers`, `next/cache`,
`next/server` и `src/lib/auth` заглушками из `_stubs/`, так что настоящее действие выполняется от
имени того, кого назвал `actAs()`. База — локальная dev-база; организации проверок одноразовые.
- `tenant-isolation.check.ts` — компания B не трогает строки и файлы компании A (файл — только из
  своей папки хранилища, по началу пути; удаление не стирает файл, на который ссылается чужая строка).
- `roles.check.ts` — каждая роль × восемь чтений аудита: открыто ровно там, где роли открыта
  страница (`src/lib/roleRoutes.ts`), плюс выборка по остальным действиям.
- `paid-caps.check.ts` — потолки платных сервисов: N проходит, N+1 — отказ словами; план после отмены.
- `everyday-work.check.ts` — OWNER и MANAGER: фото, расход, финансы, обзор, замер уже измеренной крыши.
